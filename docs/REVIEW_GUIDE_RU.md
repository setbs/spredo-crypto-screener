# Как разобраться в решении перед сдачей

Бэкенд полностью написан на **Python / FastAPI**. React отвечает за отображение и дополнительные фильтры интерфейса. Браузер вызывает только `/api/projects`; ключ CoinGecko остаётся на сервере.

## Путь данных

1. `main.py` принимает HTTP-запрос и обращается к `ProjectService`.
2. `service.py` возвращает свежий кэш либо запускает единственную фоновую задачу. HTTP-запрос не ждёт весь проход: интерфейс опрашивает прогресс.
3. `coingecko.py` получает страницы `/coins/markets` в порядке убывания объёма торгов.
4. `filters.py` отсеивает монеты по капитализации, FDV, объёму и равенству supply.
5. Для каждого кандидата запрашиваются `/coins/{id}`: здесь есть `preview_listing` и TVL. На этих данных повторно проверяются все условия. Ограничения в 25 кандидатов больше нет.
6. API отдаёт список и метаданные. React ищет по имени, ограничивает FDV и сортирует уже полученный список.

## Что стоит понимать

- `>` и `<` строгие: объём ровно $50 000 не проходит, FDV ровно $100 млн не проходит.
- `max_supply=None` и `total_supply=None` не означают известное равенство: такой проект исключается.
- `Decimal` сохраняет точность десятичных значений при сравнении supply.
- `preview_listing is True` принимает именно JSON Boolean `true`, а не строку `"true"` или число `1`.
- TVL может отсутствовать. Он не подменяется капитализацией или объёмом торгов.
- Запросы интерфейса используют одну фоновую задачу и не дублируют обращения к CoinGecko.
- Завершённый результат кэшируется на час. Прогресс сохраняется в локальном файле после каждой страницы и проверки деталей, поэтому перезапуск или повтор после ошибки не начинают работу с нуля.
- Обход страниц идёт до конца списка или достижения порога объёма $50 000. Все найденные числовые кандидаты проверяются; при большом списке это занимает несколько минут.
- `meta.status=scanning` означает незавершённую работу. Только `complete` подтверждает, что все кандидаты проверены. При `error` нужно явно повторить запрос с `retry=true`.
- Диагностическая таблица содержит реальные проверенные проекты и причины отклонения. Она отделена от списка проектов, прошедших все условия.
- Пустой live-список возможен из-за смысла `preview_listing`: это предварительные листинги, у которых может ещё не быть рыночных показателей.

## Перед отправкой

Запусти проект по README. В деморежиме можно проверить поиск `eth`, FDV меньше $25 млн и обе сортировки. В live-режиме дождись завершения скана и посмотри реальные причины отклонения. Посмотри тесты и убедись, что можешь объяснить каждое условие. Публичный репозиторий: https://github.com/setbs/spredo-crypto-screener — отправь эту ссылку через форму из задания до своего дедлайна.

Проверка реальных данных 20 октября 2026 года завершилась полностью: 2 500 рыночных записей, 626 кандидатов, 626 проверок деталей. У всех кандидатов был `preview_listing=false`, поэтому строгий итоговый список пуст. Подробности сохранены в `live-verification.json`; это отличается от прежней незавершённой проверки первых 25 проектов.
